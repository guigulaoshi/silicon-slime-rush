# 手机、iPad 和触屏

## 触屏操作

- iOS 上转向做成左下角两个"按住就转"的 ◀ ▶ 按钮，按钮自己接原生 `touchstart` / `touchend`，不走 Pointer Events，不用看不见的感应区；安卓可以保留拖动

- 只认明确的驾驶控件，普通 UI 的触摸不能变成驾驶输入

- 体感（陀螺仪）转向默认关；要做就以玩家当时的握持姿势为零点，按屏幕旋转方向选轴

- 放大一个触屏按钮时，把周围所有按钮的盒子一起量

- 手机上单独给一个暂停按钮

- 鼠标和触摸都能用的交互（比如拍照模式的自由观察）统一用 Pointer Events，走同一条逻辑

## 别让浏览器抢手势

- 在 touch 事件上拦，监听显式写 `{ passive: false }`

- 别只靠 CSS `touch-action` 保护拖动区

- 触摸监听挂在 `window` 上，不挂画布

- 菜单设 `user-select: none`

- 游戏页禁用捏合缩放，进比赛时再把缩放复原一次，两道防线各自有测试

## 屏幕、地址栏和布局

- 按实际可视区域布局，不按"全屏"算；带地址栏和真全屏两种状态都在真机上测

- 全屏遮罩和背景自己跳出安全区（safe-area）内边距

- 接手指的子元素按父元素高度的百分比定位

- 触屏的默认 HUD 尺寸按平板算，手机的"缩小一号"写在矮屏那段媒体查询里

- 按设备形态（触屏、高度、朝向）判断，不靠单一宽度断点；尺寸变化时重算布局

- 内容可能超出视口的页面一律从顶部排、允许滚动

- 每加一块内容，都在最短的屏幕上跑一遍

- 可滚动面板验"每一项都能滚到"，不验"同时可见"

- 把绝对定位的元素挪进流式布局的列之前，把那一列所有会改定位的状态逐个走一遍

- 手机样式的媒体查询放在对应的桌面样式之后，或提高选择器优先级

- 会被隐藏的元素单独写 `[hidden]{display:none}`，检查"隐藏"看实际是否可见

- 只在某种设备上才有的控件，只在那种设备上才加进页面，不要加了再用 CSS 藏

- iPad 上点一下车，整排车卡闪一下

## 离开和旋转

- 所有"玩家暂时离开"的入口（`visibilitychange`、`blur`、转竖屏）接到同一条暂停路径，回来停在暂停页

- 旋转和取消时清空所有按住状态，每种状态只由一个入口负责

- 要横屏就真做横屏约束：竖屏时安全暂停

## 全屏、震动、主屏幕和其他系统能力

- 全屏必须用真机系统级触摸验证

- 手机才有意义的 API，除了检查它存不存在，还要检查浏览器"见过"没有（`navigator.userActivation.hasBeenActive`）

- 嵌在 iframe 里（比如 itch.io）不要承诺能装成 PWA，只给"添加到主屏幕"的说明

- 没有输入记录时，初始界面按设备类型决定

## 手机 GPU 上要专门看的画面

- 远处带程序图案的着色器（比如夜景楼窗）要在手机上专门看夜景

- 手机上的 WebGL 上下文丢失要有出路

## 怎么测才可信

- 上传前用一个仿 itch 的测试页在真 iPad 上测所有拖动手势

- 真机测试用自己的构建加 `vite preview`，不连开发服务器

- 让手机能连上测试服务器：加 `--host` 绑 0.0.0.0，预览服务器放开 Host 检查

- 手机布局的结论用纯系统点击复核

- Android 上用 CDP 测试先 `page.bringToFront()`

- 手机测试一律用触摸事件，不用鼠标悬停模拟

- "调试通道能连上手机"不等于"手机上能玩"，桌面模拟也代替不了真机

- 真手机只测单人；双人分屏的窄屏用桌面浏览器缩窄窗口验证

- 在别人的真设备上跑自动化，先静音、确认对方没在用，跑完当场关页

- 插着数据线的安卓手机，用 Chrome 的调试接口直接测

- 前后对比要在同样的温度下量
