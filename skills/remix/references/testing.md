# 测试和验收

## 先证明它会红

- 新测试必须在删掉修复的旧代码上真跑一次，看它红

- 阳性对照要复现事故的真实形状，不是改动的形状

- 先看测试到底走没走到改动的那一行

- 检查分母：零个样本时，绿色什么都不说明

- 测试数据别挑默认值

- 找出那些"走默认参数、根本没经过新代码"的测试

- 量之前先确认你关掉的真是那个东西

- 守卫的门限要在"坏掉"的情况下试过尺子

- 只判上界的断言一定配下界

- 拍照和判分之前，先断言世界真的加载了、加载失败数为 0

- "满足条件就跳过断言"的写法，单独验一次那个条件在默认路径下的取值

- "跳过"不能长得像"通过"

- 前后对比测试不能自己动手把被测状态设好

- "修好之后跑了 5 次都过"不等于"很罕见"

- 有条件才生效的网址参数，要么在不生效时报警，要么搜一遍所有用法对照

- 一条测试"绿"的前提要在测试里写出来

## 断言落在玩家看得见的地方

- 视觉效果一律用"同机位、真实渲染、前后差分"作证

- 断言直接写意图，不用替代指标

- 断言"看得见的东西变了"之前，先断言它可见

- "在画面里"和"看得见"是两回事，位置断言要把会盖在上面的东西一起算

- 用最宽的真实值测溢出

- 检查素材本身时，直接读实际加载的那张图

- 量"变亮/变暗"时断言乘进去的系数，不数被点亮的像素

- 测量和截图放在同一次 `page.evaluate` 里、先冻结时间再做

- "天空从缝里漏出来"这种人眼难判的问题，用染色法量

- 无头截图截不到的东西，别当成页面坏了

- 键盘操作的验收开始前先把鼠标移开

- 离线渲染图不是游戏里的效果证据

## 等事件，不等时间

- "按键 N 秒后断言某事已发生"一律改成等那件事本身

- 一闪而过的状态，在页面里用观察器当场记下来

- 在等待条件成立的那一帧里，直接把数据一起取回来

- 断言别盯着会被定时器正常改写的状态

- 等待条件用明确的就绪信号

- 先清零或记下基数再计数

- 等动画终态截图，用 Playwright 的 `animations: 'disabled'`

- 制造"数据晚到"要在字节真正的来处制造

- 暂停测试要像玩家一样松开按键再重按

- 测试里的"快进/重置"函数有自己的时序

- CSS 过渡不在 `getAnimations()` 里，“等动画结束”对它没用；要等的是“这个数不再变”

## 软件渲染和真显卡

- 浏览器测试默认用真显卡，软件渲染只留给像素比对

- 只在真显卡上才成立的断言，跟一个开关走

- 关键物理验收在真显卡上跑

- 录像、声音相关的测试在真显卡下跑，红了先做最小对照

- 自己 launch 浏览器的脚本，要显式写 headless、静音和 GPU 参数

- 需要导入源码模块的 GPU 用例，连开发服务器

- 构建版和开发版两条路径都要有测试

- jsdom 有它测不了的东西，别在里面硬测

- 单测替身看不见构造顺序和真实接线，这类问题一条真浏览器 e2e 胜过多条单测

- 被测试引用的模块要同时兼容 Vite 和纯 Node

## 假红：先查环境，再查代码

- 测试用自己的端口，永远不借别人的服务器

- 改了源码先 build 再 preview

- 预览服务器用可控的启动/停止接口起，用完就停

- 一红先看 load average，并按整套并行时的耗时给预算

- 重测试单独分组、独占浏览器跑，不要放宽产品断言或抬高全局超时

- 默认超时照最便宜的用例定，贵的自己申请

- 长测试要能从外面看出是慢还是卡死

- 满载时偶发的一条红，单独重跑确认，并在记录里写明是哪条、单跑结果

- 拷过来的依赖目录，先离线核对它和锁文件是否匹配

- 别的分支上"实测过、有数字"的结论，搬之前在当前主线上跑一遍

- 复制原作后第一次跑手动开关的测试（`*_QA=1` 这类），冒红多半是测试自己过时了

- 带 skipif、读缓存的测试，缓存一删就悄悄跳过

- 同一条测试在并行全量里反复红、单独跑一直绿，就别再查它了，把它挪进单线程独占组

- 一轮里红了九条，多半是一处毛病，不是九处

## 视觉基线和像素比对

- 基线必须真比对，并做阳性对照确认它会红

- 先把一帧里的不确定源一个个钉死，再让比对判对错

- 像素比对跟录图时的渲染器绑定

- 临时截图、正式参考图、基线三者分目录

- 基线图不进 git

- 像素阈值用"有目标图层 / 没目标图层"两次对照来校准

- 随机粒子的像素断言，扫多个相位累计，或先断言前提

- 干扰物体在那次测量里临时藏掉，量完恢复，不放松断言

- 静态截图证明不了动态不闪烁

- 存进仓库的截图是会过期的快照

- 前后对比图，在旧版本的临时副本里拍

- 数地标像素前先把半透明网格藏掉

- 开工前先给 `original/game/e2e/shot.spec.ts` 加一个定点模式

## 测试数据和元素定位

- 测试跟注册表对账，不写死数量

- 用目录 ID 定位，不按数组下标、不按玩家文案

- 用显式清单列测试对象，不扫目录

- 交互用 `data-action` 这类稳定标识定位

- 断言读产品常量和共享 schema，不抄数字

- 新加的前置流程，测试要显式声明

- e2e 目录纳入类型检查，全局只保留一份声明

- 几何常量用最高和最矮的车都验一遍

- 别拿真实赛道的某一米当测试材料

- 数像素时的纯色材质要新建，不要克隆场景里的材质

## 物理和驾驶测试

- 挪车、测速都走游戏自己的入口

- 引擎读回来的值用容差比较，配置源本身精确比较

- 加速测试要加速整个游戏步，并断言实际的 timeScale

- 完赛必须在合理的模拟时长内

- 多车整局成绩是噪声，调驾驶逻辑要一把能证伪的单车量具

- 依赖驾驶技术的场景不做回归检查，拆成物理能力检查

- 测 AI 时把玩家车停到不碍事的地方，别让它参赛

- 测试台要和正式赛道一样有路面和护栏

- 简化物理证明不了真实赛道能通过

- "第一次着地"证明不了落地稳定，要断言持续落稳

- 判断撞车要对照相同物理时长的基线

- 测试选有明确几何保证的路段

- 版本验收跑一次全车型满编

- 守卫报偏差时重测整张表，不去放宽门槛

- 慢测试先找有没有现成的空间索引可复用

- “9 辆车、正反两个方向、每种天气”的 AI 完赛时间全量实测，是最早发现路面问题的探测器

- 量出数值不等于知道去哪儿看：让失败的测试自己留下“出事地点”

- 一根射线打不到，不等于那儿没有东西

## 换掉原作赛道时，测试怎么改

- 先看有没有“数据不在就跳过”的测试

- 按“测试靠的是哪条属性”挑新赛道

- 比例型的断言常常量的是赛道长度，不是被测的东西

- 改指向不只是改赛道 id

- AI 完赛时间表只量这条赛道真会出现的车

- 一条测试连着好几处对不上，多半不是好几个小毛病，而是它的前提被新赛道悄悄换掉了

- 按米数摆的东西，换了赛道先换算成屏幕上的像素再看

- “至少要有两种”这类多样性断言，在数据本来就只有一种的地方是在要求造假

## 覆盖面和测试节奏

- 定期跑全量浏览器测试，并清楚知道回归窗口有多宽

- 给一种进入方式加前置流程时，列全所有进入同一下游的入口

- 改存档键、删行为、改默认值之前，按多种写法搜全依赖

- 默认值只写一处

- 组合维度各测一次，不做全排列

- 日常和全量测试入口只读，生成证据要显式开关

- 生成地图/资产的命令本身要有测试跑一遍，拿产物当证据时同时报退出码

- 搜旧文案时拿历史版本做阳性对照

- 路线改短以后，可能没有一条赛道长过流式窗口（前 1500 米加后 300 米），切片卸载就没人测了

- 菜单卡片图拼成一张联图一次看完

## 如实报告：证明了什么，不能声称什么

- 每层验证写两栏：证明了什么、不能据此声称什么

- 性能数字必须注明机位和机器

- 估算写"估算"，没跑写"没跑"

- 读测试输出看汇总行，别截断报告

- 绿色只说明断言成立，不说明你测的是你以为的东西
