# 界面和中英文案

## 中英文案

- 换成中英以外的语言，先按清单改代码里写死的两种语言

- 所有文案走 i18n，不写死字符串

- 地名用词规则用测试钉住

- 界面一次只显示一种语言，按浏览器语言初始化，随时可切换

- 场景里的本地化物件和菜单、HUD、广告牌共用同一个切语言事件

- 游戏名收成一个函数，按当前语言返回，全仓只从这里取

- 换了名字就量一遍它在首页占几行，两种语言都量

- 改名要从显示入口和生成入口两头扫

- 单位和它的语言切换一起给，并统一走一个格式化入口

- 测试从 locale 文件读文案，不要在测试里再写一份

- 改了语言文件要重启开发服务器

- 文档里的 i18n 键示例从实际数据里反查出来，不手写

- 批量改名时先批量替换，再单独写“曾用名”注释

- 没有官方中文名的外国街名，在中文界面里保留原文

- 分享卡上的每个数字都对照结算页核一遍

- canvas 上画中文，先确认字体覆盖要用的每一个字，逐字检查没有方块

## 界面主题

- 先量界面的颜色有多散，再动手

- 把颜色收拢成八九个按用途起名的主题变量

- 变量名加一个别人不会用的前缀

- 第一遍按原来的颜色填变量，拍一组图跟改之前逐像素对比

- canvas 画的东西（分享卡、结算图、水印、3D 场景的背景色）跟样式表用同一个主题对象、同一套混色算法

- 内容色和标志色不算主题

- 界面的冷暖由面板底色决定，定色调时先看它

- 图标跟着新游戏的主题换，不沿用原作的

- 加一条守卫测试

- 界面截图要自己拍，别指望视觉基线

- 主题对象管不到代码里写死的颜色，换色后逐文件搜一遍颜色字面量

## 名字怎么叫

- 跟人说车、说路线一律用游戏里的显示名，内部 id 放括号里

- 语音转写里拿不准的同音词，当场问一句

## 布局和尺寸

- 菜单和游戏画面跟着屏幕长宽比铺满，不要锁死 16:9 整体缩放

- 量尺寸用布局像素，分屏布局拿真实矩形量

- 改一个控件的尺寸，就量它和所有邻居的矩形

- 往排满的弹窗里加东西，先量是谁撑着行高

- 选中态的边框和未选中一样粗，高亮用内阴影

- 窄卡片放不下一行链接时，卡片改上下叠放，并加浏览器测试守住单行不截断

- 改容器的 `padding` 或 `overflow` 时，搜一遍子元素的位移和阴影

- 不想被程序化滚动的外框用 `overflow: clip`，不用 `overflow: hidden`

- 删掉翻页箭头时，同时补上滚轮横向滚动

- 新页面包进一个隔离外壳，统一消掉全局样式的影响

- 加类名前先全仓 grep 一遍

- 覆盖样式要提高优先级，或统一放进后加载的文件

- 调换按钮顺序时，间距规则跟着“位置”走，不跟着按钮走

- 修遮挡要顺着玩家的下一步看

- HUD 文字加深色衬底或阴影

- 路边广告牌按开车经过时的实际像素设计，不按近看设计

## 焦点、键盘和弹窗

- 一个键在一个状态下只产出一个动作

- 任何模态框打开后，终止这一帧剩余的动作；关闭时按帧开头的输入状态消费；所有模态框共用一个分发

- 确认键的归属在唯一的通用拦截点上修（`defaultPrevented` / `stopPropagation`），不要复制一份键盘监听

- 主按钮不可用时焦点放在哪，集中在一个地方决定，每个页面都要进名单

- 进入暂停页默认选中“继续”

- 一个对话框被多个入口打开时，在每个入口里把 ×、Esc、回车都走一遍，并看清每个入口传进来的是什么

- 菜单内容变高后，在处理键盘选择的同一个入口里 `scrollIntoView`，并用真实键盘测试覆盖

- 列表原地更新，不整体重建 DOM

- 设置里每一种行都考虑“确认键不带值”这条路

- 新表单复用唯一的保存与生效入口

- 捷径要把原流程的守卫原样搬过来

- 加 ARIA 角色前，先搜一下按角色定位的测试

## 状态和生命周期

- 离开一个界面时，收尾要在改状态之前判断

- 初始化、从失败返回、切语言是不同的动作，在 reset 入口分别定初始状态

- 只在明确“打开菜单”时把选择归零

- 生命周期不同的消息不共用一个显示槽位

- 带时间窗的 HUD 提示看比赛状态或用真实时钟，不用比赛计时

- 倒计时阶段单独处理 HUD 读数，并让测试覆盖倒计时这一段

- 在流程前面插入新步骤（比如开场动画）时，回头查所有依赖初始状态的入口

- 读到还没开放的默认项就回退到已开放的

- 加载百分比只用同一种时间相减，显示的进度只增不减

- 可复用界面的重置必须在显示之前

- 进度条的动画放在整条进度条上，按真实加载进度走

- 加载完直接进选择界面，第一眼就是地图

- 删一个界面入口时，往下追到只有它在读的数据和文案，往外追到只有它能接住的流程

## 地图和数据图

- 先想清楚玩家在这一屏问什么，再决定画什么

- 地图方向的投影抽成纯函数，对多个朝向逐一断言

- 小地图按线段裁剪，不按端点裁剪

- 陆地上画淡淡的公路网，让它一眼就认得出是陆地

- 横向比较的条形图按 min..max 区间归一化；越小越好的量不画成条，直接写数字

## 画布绘制

- 画布上用新 API 前，先查构建目标浏览器支不支持

- 按内容的底部推算下一个元素的位置，先量再画

- 用 emoji 区分类别时，先确认每一种都分得出来

## 验收方法

- 视觉问题先逐帧录下每个元素在干什么，再猜原因

- 外观改版逐屏拆成小任务，每屏都和原型并排截图比对

- 定样式时做可切换的样品，放在真界面里让人试
