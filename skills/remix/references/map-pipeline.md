# 地图管线

## 核心要求

- 地图是事实，赛道是设计

- 贴地的一切都从最终成品地形和真实路面取高度

- “路上不许有楼”查装配好的最终三角形，写进构建、压路就让构建失败

- 弧长、平整区边界、路口分析、碰撞类型表、延伸路径，每样只有一份

- 地图数据固定成入库快照，缓存键覆盖全部真实输入、但只投影到消费者真正用到的那部分

- 修一个视觉洞，以一把能执行的尺子归零为“修完”

## 取数和快照

- 按区域取一次 OSM，gzip 压缩后入库，记下来源 URL、日期、许可证（ODbL 1.0）、投影原点和投影方式

- OSM 和全球高程只是底子，当地的公开数据有就去下

- 拉 Overpass 要多个镜像轮换加指数退避

- 海岸线、公路网这类大范围数据整个区域拉一次、整块缓存，再按取景框裁

- 高程瓦片远近分级：远景用粗的，近处才用细的

- 分清“取数范围”和“出图范围”，并按路线逐栋检查建筑是否落进了出图范围

- OSM 缓存要盖住“建出来的那条线”的走廊，而不是航点围成的方框；重拉只扩不缩

- 改了管线代码，就把重新生成的入库数据一起提交

## 坐标、高度和朝向

- 坐标一律用米，复用原作的投影（`original/pipeline/sr/geo.py` 的 `LocalFrame`，等距方位投影），不另写经纬度换算，不为镜头方便压缩比例

- 凡是贴地的东西（护栏、竖板、墙、植被、广告牌）都从最终成品地形取高度，别从原始 DEM 取

- 把“路面比路线样条高多少”写进数据契约，管线和运行时各有一条测试回读

- 往路上放东西、算天降物体落点，用射线查真实物理表面，不用中心线高度

- 管线（Python）和运行时（TS）各抄一份的几何常数，加一条断言两边相等的测试

- 朝向换算收拢到一个函数，改完对所有定向物体做一轮旋转审计

- 支路上的设施按支路自己的方向定轴

## 读 OSM 建筑

- 一栋楼有 `building:part` 分件时只挤出分件，跳过外轮廓（outline）；保留内院的洞

- 分清“值很小”和“没写”

- 读 `min_height` 当楼底，不要让分件都从地面长起来

- relation 先把 member 拼成完整外环再挤出，inner ring 做成真正的洞并给内院也砌墙

- 大体块的地基按整条边界上的最低地形点定，不按重心

- 高度标签先判单位再取数字；取值顺序：`height` 标签 → 层数 × 3.5 米 → 按类型和占地估

- 每栋楼记下高度来源（地图标签 / 公开总高按分件比例缩放 / 照片估计 / 默认估算），道路记路宽来源，补出来的桥面标“补全数据”

- 建筑面积下限做成参数，地标区调小

- 地标分组由 relation 成员推出，漏标的手工补，并检查“完全落在地标轮廓内却没归类的分件数为 0”

- 挤出前全管线统一按 `building` 标签过滤，并加回归测试

- 专门建模的地标只由一个读取器提供轮廓，接手的 OSM 实体必须从通用建筑和远景天际线里一起剔掉

- 离岸结构（桥墩、防波堤）单独过滤，别让高程回退规则和建筑回退规则给它们长出楼和草

## 路线怎么定

- 生成路线后按整个路面脚印做净空检查，冲突时挪路线，不挪地图

- 路线文件声明必经点（`mustPass`：要让人看见什么、坐标、最远多少米还认得出），坐标取 OSM 建筑轮廓的重心，构建时测量、超了就失败

- 路线要经过主干道和地标正面，让玩家在正常车速和跟车机位下看得出建筑

- 路宽是设计参数，不是测绘结果；给一个全程最小半宽（原作 6 米）

- 路面半宽按弯道半径封顶：半宽上限 = 0.7 / 曲率，下限 3 米，用测试钉住；发夹弯两端各加强制航点

- 防止路由抄别的路、来回走同一段

- 真实路网来的路线只要有急折返角就削掉，并在真浏览器里用最长的车跑一遍

- 路线允许的最小转弯半径由车队里最长的那辆车定，不由路面宽度定

- 删“原路折返尖刺”时带上长度判断：绕回同一路口超过 250 米就是一圈

- 选路段时 `highway`、`access`、`surface` 连同几何实际覆盖一起查，写成断言

- 重采样路线时保留 OSM 的 `layer`、`bridge`、`tunnel`，判断路口时逐项匹配

- 一遍路网分析同时产出主路路口和支路封闭点，路障和路口标线吃同一个结果

- 特殊路面（机场跑道等）用实测分段宽度，不画街道路口标线；要封路的大障碍只放在自身半径能完全封住的窄段

- 设计约束和它的例外写进能执行的测试，至少写进常驻文档，不要藏在路线文件的注释里

- 起跑摆车只用“中心线左右两侧”这种不依赖标线的位置

- 起点别放在直角路口

- 路线砍短之后，按条数配的东西都按新长度重算一遍

- 中线颜色和靠哪边开，按赛道声明

## 弧长、里程和位置

- 三维弧长在导出、量化之后只算一次，运行时全部读这一份，禁止二次累计

- 测车的位置用直线距离或局部（邻近弧长窗口内）投影，不做全局重投影

- 同一件东西的位置和形状用同一种弧长采样

- 正反向切换只放在一个统一的方向转换入口，并加一条“远处驾驶不受首段影响”的测试

- 环线上按首尾相接的环线距离算间距，多套物件（比如两种难度的障碍）放在一起统一排

- 挪路线的改动必须连带更新绑在弧长上的东西（取景点、验收机位）；起跑位姿只认一个主（如 `track.start`），视觉验收直接复用，不另写一套朝向公式

- 没有路线穿过的切片，里程区间按到切片矩形的距离算；纯路外景物写空数组，由运行时按距离加载，schema 同步放开

- 起终点沿真实道路延长时，延伸路径只有一份，可见路面、地形裁切、坡度、护栏、安全碰撞、AI 停车都读它

- 路线端头外的道路按点逐个过滤，端头处纵向延伸和横向覆盖分开判断

- 起终点“在路上”按到最近那段路的距离量，不按到最近路口量

## 地形和路面几何

- 带状网格支持左右两条边各取自己位置的地面高度；人行道靠路一侧和路面齐平、外侧跟地面走

- 路面横向多采样几个点；“平整区到哪为止”只认一个字段

- 共享的路面生成器要改，就加一个显式参数、默认行为不变，改之前先搜全部调用者

- 按实际路面多边形裁切地形，不用“三角形重心在边界内”代表整个三角形

- 沿路沿补一圈采样点，让地形三角形在路沿处干净断开；路面边缘往下挂 1.2 米裙边兜底；路面正下方会从沥青里露出来的地形三角形直接剔除

- Delaunay 挖洞时，重心加三条边中点一起测；远景地形和流式地形之间留 20 米重叠

- 每个生成器末尾统一按法线校正三角形绕序，加回归测试

- 闭合赛道的路面、裙边、人行道都要首尾闭合

- 挡土墙只在紧邻路肩就有 4.5 米以上高差时才立，并限高

- 护栏和道路边界按真实路面网格裁切，护栏和立柱走同一个“离路面净空”判定

- 支路跑到赛道路面底下的部分直接丢掉，让赛道那层必须赢；支路画全长，在离赛道边缘 30 米处横放一排路障

- 地表先按类别合并，再按覆盖优先级（小路 > 道路 > 铺装 > 草地 > 园区 > 底板）做布尔裁剪，输出互不重叠的地面多边形，渲染和碰撞吃同一份三角形

- 路面标线用贴路面的薄条几何，每条线用“它是哪条线”做键，抬高量从路面算，车道数从赛车面宽度推，亮度大部分靠自发光

- 沿中线平行偏移出来的东西（人行道、路缘、护栏线），在急弯内侧不许越过弯心

- 城里的高程数据带着屋顶、树冠和楼群，先做成“裸地”再建赛道

- 高楼和高架还要再削一刀：高楼旁边用“开运算”、赛道不走的长高架从地面里挖掉，也不画在地上

- 急弯过后路面上会出洞

## 建筑和路面的净空

- 建筑轮廓先和赛车面做差集再挤出，小于 12 平米的碎片丢掉；碰撞和网格走同一份裁剪结果

- 让路余量按“护栏 + 人行道 + 一米空气”定（原作 3.7 米），测试判据用人行道外缘这个事实，不复述过滤条件

- “路上无楼”检查放进构建、查装配好的三角形，压路就抛异常让构建失败；把修复去掉再构建必须红

- 远景层同样不许有任何东西站在任何一条路上，用真正画出来的几何和真实可行驶面判相交，不用距离近似

- 同一种“只测重心”的错修过一次，就推广检查到所有生成器

- 垂直分层：生成、守卫、测试三处用同一套分层语义，俯视脚印冲突只在同一高度层内判

- 只有真正贴地的那部分路面才参与挖建筑和地形（用地形自己的高度函数判断）；比桥面低 3 米以上的建筑不算压路；补一条“路面低于地面时必须照挖”的反向用例

- 建筑避让区用沿路变宽的多边形，别按最宽处统一缓冲

- 碰撞数据挂到一定存在的节点上（比如该类排序后的第一个），只挂一次，并加测试

- 楼体碰撞沿地图外墙和内院边生成薄墙盒，内院保持开放；门洞只做近景观察，不作为穿楼捷径

- 地标切割检查：互相穿过的封闭壳，切出来的线先求并再拼成多边形

## 地表和植被

- 地表颜色只从 landcover/natural 读，不从 landuse 读；植被能不能长由自己的密度表决定，两种筛选分开

- 园区范围（`leisure=park/garden`，grounds）和真实草地（grass/forest/meadow）分两类地表，只有后者渲染成草

- 给特殊地块上色前，先问默认那一大片地面是什么颜色、对不对

- 忠于 OSM 不等于忠于现实，按地区推翻 OSM 要单独决定并写明

- 植被：OSM 单棵树按位置放，林地按面积撒，草地不撒；撒点避开楼、街道、停车场

- “这块地没标注时是什么”只能有一个主

- 撒点范围要覆盖开车望出去的那一圈

- 随机种子用路线 id 的 CRC32 之类的稳定哈希，不用 Python 的 `hash()`

- 按面积撒东西后，逐张画面看各类用地，不只看总数

- 照着地图画，缝会出现在“数据变化的地方”，而不是“现实变化的地方”

- 分区多边形（住宅区、商业区）不能拿来上色，拿来摆东西也要先量

- 密集老城里，地图上没标用途的空地是铺石的街道和广场，不是草坪

- 地图上没有地被标注的地方（比如稀树草原），树的输出是零，而且不报错

- 高程数据画不出来的地形（石柱林、孤峰）自己生成时，顶上的绿和树收在顶面轮廓以内

## 水、海岸和桥

- 海用高程判（Terrarium 瓦片自带海底地形，零高程线就是海岸线），再给每条路线一个水面高度参数兜底；内陆的河和湖不能这样判，见下一条

- OSM 海岸线约定“陆地在左”，测试要问“某个内陆城市是不是干的”，而不是“多边形闭合了吗”

- 开场世界地图上的内湖要“开缝”才画得出来，而这件事有两个坑

- 闭环简化单独实现（先拆成两段，或选最远点做基线）

- 河面下沉，水域从碰撞地面里扣掉，加岸墙；测试断言碰撞地面与水面交集为 0

- 有能掉下去的地方就要有恢复路径：车低于阈值就复位

- 逐条核对每条桥道路是否有对应的桥面；没有就按中心线和路宽补出来，标“补全数据”，并全量数一遍确认无同类剩余

- 从地面里只扣水，保留桥下干地；普通岸墙在桥口让路，桥下仍封住土体截面；桥的拱面与碰撞共用同一份几何，桥孔真正镂空

- 桥段不做地形融合、不立挡土墙

- 对向道路和桥层单独算高度，桥头位置用道路端点加 `layer`/`bridge` 判断，不信 OSM 的切段点

- 窄河会被地形三角形跨过去

- 跨在水上的桥做成独立的模型，按管线实际给它的底面高度建

- 内陆的河湖从 OSM 的 `natural=water`、`waterway=riverbank` 轮廓里画

- 高程采样碰到没下载的瓦片会读成 0 米，跟海一模一样

- 远景按高程判水时，河床也会被当成海

- 填海出来的沿海平地，高程分不出海和陆，海面照 OSM 的水面画

- 桥面永远不低于它跨越的地面，延伸路和赛道在接缝处严格对齐

## 远景

- 远景看不看得见，四样一起查：数据半径、相机远裁剪面、近处的雾、真实遮挡

- 高空或远眺镜头用“整条赛道”的加载窗口

- 首页环绕这类镜头下的一个洞可能有好几个成因，管线和运行时都要查

- 远处的地标要站在玩家真看到的那张远景网格上

- 尖山在粗瓦片里会被削掉几百米

- 远处的名山被远景网格削平

- 远景的半径要够到路线自己声明的山；高山按雪线换材质

## 切片和流式加载

- 索引和数据包要能互相校验（版本号或哈希）；改打包方式时回头审下游所有“这种输入不可能出现”的假设

- 每个异步地图请求绑定发起时的世界和观察者（abort signal），回来时判断“还需不需要”，而不是判断“session 赋值了没”

- 创建车辆刚体之前，先确保出生点周围的碰撞切片加载完（复用现有加载和重试），并用“故意延迟加载”的测试覆盖

- 节点到碰撞类型的对应表只有一个主（契约文档），导出器和运行时的表都用测试钉在它上面，第三处副本从导出器派生；材质名表同理

- 烘进切片的游戏参数（道具尺寸等）只留一个来源，改完必须重跑切片并在真实画面上确认

- 路面按瓦片切开时，交界处可能漏一条缝，车轮会掉进去

## 缓存、新鲜度和构建产物

- 新鲜靠输入哈希；哈希要覆盖全部真实输入，包括被 import 的文件

- 缓存键只投影到这个消费者真正用到的那部分，不拿整个目录或整个共享文件的哈希

- 快靠“只建马上要用的那条赛道、谁都不建第二遍”

- 所有派生产物（切片、贴图、菜单地图、预览图）都接进同一套新鲜度检查，别留手动步骤

- 改了共享配置，先单独跑一遍资产生成把缓存做好，再启动浏览器验收；超长路线要么缩短，要么单独跑

- 要停构建，就连同输出目录（原作是 `original/game/public/tracks`）一起清掉再重来

- 枚举赛道一律读路线清单文件，不扫构建目录

- 构建时用“是否可玩”的判定过滤产物，不另立黑名单；删一条赛道按清单走完整条链

- 删掉的赛道要是别的测试“借来用”的，按它被借的那个性质换一条，别跟着删测试

- 纯显示层的改动（比如道路在游戏里显示的名字）放在运行时显示层重命名，保留 OSM 几何

- 同一个名字同时存在于界面翻译和管线生成的数据里时，两处一起改、回归测试同时锁住两处；相邻、容易串线的两条路线作为一组映射一起锁

- 测试夹具的尺寸从正式配置读，不要写死

- 拍“改前”对比图时，先把旧代码放回去，让它按旧源码重建地图

## 管线的速度

- 路线变长时，把“对全量数据求交”改成有界查询、局部道路空间索引、增量筛选，并保留“新旧算法结果等价”的测试

## 验收怎么查

- 视觉洞的验收取多个方位（原作用八个），配一把能执行的尺子（比如“水平线以下不许出现天空像素”），以尺子归零为“修完”

- 每个修复都做反向验证：把修复去掉，检查必须红

- 先定位问题在哪一层（流式切片、远景、运行时装饰），再修

- 报数字前沿真实调用链确认数据从哪来

- 地图测试能证明的和不能证明的分开写
