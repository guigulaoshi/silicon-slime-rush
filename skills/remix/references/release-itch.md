# 游戏放在 itch.io 上：嵌入、外链、署名

## 作者外链和选平台

- 把作者外链当成游戏的一部分：换成你自己的账号和地址，保留入口、二维码、分享出口这整套机制

- 选任何发布平台之前，先读它的开发者协议，对照游戏里所有外链、二维码和分享出口

- 按钮文案写玩家能得到什么（More Games / 更多游戏），不写平台名

- 把最想让人点的外链放在玩家第一眼就看到的位置（不用滚动就能看见）

- 正式游戏地址只在一处定义，所有分享出口都从那里读

- “有地址”和“空地址”两种构建状态都要有回归测试

- 路边关注牌、二维码这类“平台身份”要和文案作为同一个本地化对象一起切语言

- 二维码用无损 PNG，并放进真实资产构建路径里验证能扫

- 不要为了“以防万一”再维护一套 CDN 镜像

- 会挡脚本、回 403 的站点放进外链白名单之前，在浏览器里逐个打开核对页面标题

## itch 嵌入环境：跨域 iframe、剪贴板和手势

- 一次点击里的手势只能有一个消费者

- 剪贴板 API 被拒时退回“选中文字 + `document.execCommand('copy')`”

- 复制、系统分享、取消，各给一个明确反馈；接口不存在时走后备路径

- 做一个仿 itch 的跨域宿主页，`allow` 清单照 itch 原样抄，改触摸和剪贴板的东西先在那里测

- 靠地址参数的功能（挑战链接、直达某条路线）一定在真 itch 嵌入环境里验证

- 分享文字、图里的地址、二维码里的长期链接只指向商店页

- 不要把托管地址写死进包里

- 需要绝对地址的东西（Open Graph / Twitter card 的图片地址等）留一个发布后再填的口子，不要在构建时猜

- 地图包整份下载一次、在内存里切，不要按 HTTP Range 分段取

- 首页音乐的自动播放要在真 Chrome 里测

## 商标、许可、地图署名和 AI 披露

- 去商标化时把中文名单独查一遍，地点和园区名也要处理

- 开源许可沿实际依赖图收齐，版本和链接从唯一来源读，不手写

- 用了 OpenStreetMap 就在游戏的关于页和发布说明里写署名

- AI 生成的素材在 itch 的 AI 披露栏如实勾选，并写进上架清单
