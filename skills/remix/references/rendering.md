# 画面和光照

## 核心要求

- 写实画面按“怎么搭出写实画面”那一节的配方来

- 地面各层做成互不重叠的多边形，不靠叠放顺序或颜色排序防闪

- 雾、远裁剪面、天空穹顶半径、阴影覆盖都从同一个"玩家实际看多远"推出来

- 截图就是验收面

- 量"玩家看不看得见"时，用玩家能拿到的最坏那台相机

## 怎么搭出写实画面

- 场景一律用 `MeshStandardMaterial`，光照保持连续

- 天空用 three.js 的 `Sky`，再用 `PMREMGenerator` 把它烘成环境贴图给 `scene.environment`

- 用 ACES 色调映射，曝光和环境强度从低往上调，以实际截图为准

- `renderer.outputColorSpace = SRGBColorSpace`，颜色贴图（包括 `CanvasTexture`）都标 `SRGBColorSpace`

- 车辆保留 GLB 自带的车漆、玻璃、橡胶、金属材质，不被场景材质统一覆盖

- 贴图到货时把材质的标量重置为 1 再重调

- 别把光影画进颜色里

- 白天用下午的太阳，不用正午

- 天空颜色拿实拍照片校准，不用"深蓝""浅灰蓝"这类词来调

- 天空和雾接成一体

- 换掉一种画面方案时，把所有运行时入口都查一遍

- 材质库按名字挂材质，找不到就用洋红色报错材质

- 大片同一颜色的地面，就是“还没贴图”的样子，但光调颜色治不了远处的空

- 最该查的那个颜色，是“什么都没说的时候用哪个”

- 砖要按开车距离读得出来的尺度画

## 闪烁和深度冲突

- 地面各层在管线里做成互不重叠的多边形，而不是叠放

- 近裁面调大只是改善深度精度，替代不了删掉重叠面

- 同一轮廓上别叠两层几何，要叠就外扩偏移；贴地印记统一用 `polygonOffset`

- 大面积贴字的表面单独处理深度

- 着色器里现算的高频图案，按 `fwidth` 算像素覆盖面积自己做过滤或淡出

- 原作的楼窗过滤在“满城都是远处高楼”的地方不够用，开着车看远处的楼，窗户照样闪

- "不闪"要看连续帧和驾驶视频证明，静态截图证明不了

- 没有分类计数或性能对照，不把闪烁归咎于面数

## 阴影

- 只让该投影的物体 `castShadow`，地面只接收不投射

- 远近之间出现一道明暗分界，先逐项排查来源：阴影覆盖、模型切换、雾、纹理过滤、剔除

- 单独加载的模型要自己开投影

- 阴影生效要用同机位开/关阴影的渲染差分作证

- 按距离分档开阴影，只在跨档时遍历地图切片，不每帧遍历整个场景

## 雾、距离和远景

- 调雾、LOD、阴影距离这类按距离起作用的参数之前，先量清玩家实际看的距离段

- 真雾从近处（原作 8 米起）指数变浓，贴地浓、往上淡，空间上一团浓一团淡

- 雾的范围、相机远裁剪面、天空穹顶半径都从远景半径推出来

- 距离场、椭球场的渐变先换算成线性距离再选过渡区间

- 粗糙土石面的法线保留一点向上分量，让它吃到天光

## 夜晚、车灯和发光

- 夜晚要连车前灯一起做，不能做成"诚实的月光"

- 夜里给地标打光要像地上的投光灯：从地面几个方向往上照，只亮朝灯的墙面，背光面留暗、屋顶几乎不亮

- 摩天楼夜里不是从地上打光，是整栋立面自己亮

- 楼窗夜里的自发光要比直觉低得多，灯色偏暖

- 车灯真实照亮路面，不用一个随车平面假装

- 路灯的实例化光锥底部和地面光斑共用"道路平面上的目标点"，斜照路中央

- 刹车光晕用平面加径向渐变贴图，不给每辆车挂真光源

- 透明体积效果要三道证据：可见性参数、朝向几何、最终像素

- 光的效果在玩家实际机位下量亮像素，不看侧面截图

- 从上方只看得见正面的贴地透明效果用单面材质

- 半透明的薄物体保留饱和底色，单独限制边缘光强度

## 水、天气和粒子

- 水面在着色器里叠三列不同方向、波长、速度的正弦波打散法线

- 雨、雪、灰尘这类环境粒子存在世界坐标里，只在绘制时围绕镜头绕回

- 分屏时，镜头相关的效果（雨滴、湿镜头）在每个视口真正绘制之前，按那个视口的相机和车重新解析

- 要让效果"落在物体表面上"，用材质的 `onBeforeCompile` 注入共享的世界坐标光场，不用全屏后期

## 着色器、材质和实例的坑

- 改 `onBeforeCompile` 后拍一张带车的截图，先看主体在不在，再看要验收的东西

- 注入前检查这个材质是否已经被注入过

- 着色器里所有 `pow` 的底数用 `clamp`/`max`/`smoothstep` 保证非负

- `InstancedMesh` 的 `instanceColor` 等实例属性在材质第一次编译前就分配好，哪怕先填默认值

- `InstancedMesh` 挪位压缩后清掉尾巴，或把 `count` 设成有效数量

- 多次写入同一个 buffer 时合并上传范围，不要覆盖

- 按形状算范围时把顶点着色器里的变形算上

- 投影到车身上的贴花先渲一张最外层深度图做遮挡

- 贴花、液迹只落在明确是地面的表面上，碰撞法线只用来描述碰撞

- 立面窗户用墙自己的 UV 画，屋顶用世界法线判断

- "颜色由谁决定"只留一个地方

- 每加一段现算的着色器，就在交付检查里挂一条浏览器测试：白天、夜里各开一次场景，控制台出现着色器编译错误就判红

## 渲染目标、上下文丢失和画质切换

- 每新加一个"只画一次进渲染目标"的缓存，同时写好 WebGL 上下文恢复后的重画路径，并全仓库搜同类调用

- 渲染器重建（比如切换画质）时，所有存"持久内容"的 `WebGLRenderTarget` 都要重画或迁移

- 凡是另起一个 WebGL 渲染器的地方（选车页 3D 预览等），都从同一处读画质

## 相机和构图

- three.js 的 `fov` 是垂直视场角，追尾相机收在 58～76 度

- 定首页镜头构图时，把 UI 面板挡住的那块从画面里扣掉

- 固定物理步长下，"上一步/这一步"两份状态跨显示帧保存，按累积时间插值

- 占位背景尽量取场景刚画过的最后一帧；必须出厂的图用脚本出，不手拍

- 菜单卡片的机位按“地标在前方多少度”挑，不按“离地标最近”挑

- 截素材图前关掉所有 UI 层，并加一条亮度检查防回归

- UI 布局判据挂在容器上（container query），不挂在视口上

- 首页的环绕镜头换赛道后重扫整整一圈，别从原作的起始角度往后扫

## 排查方法

- 可疑光源逐个关掉对照，比读代码猜快

- 想确认某一层是不是 3D 场景的一部分，逐层隐藏

- 怀疑"A 透过 B 显出来"时，把 A 刷成不可能的颜色（如洋红）跑一次

- 加调色、泛光这类后期时，场景画进去的那张离屏图要开多重采样

- 动画效果先截改前，再按时间轴多帧对照

- 关一种效果前先列全它所有的出口

- 加"在不在里面"这类判断前，先找现有的那个复用

- "进去/出来"类效果用同一次连续行驶的进去前、在里面、出来后三帧验收，第三帧必须干净

- 判断玩家看不看得见，量玩家能拿到的最坏那台相机

- 截图就是验收面，自动断言管不到观感

- 视觉升级时同时推进像素基线和"同一镜头下的几何数量"
