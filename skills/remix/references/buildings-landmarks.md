# 建筑、地标和模型

## 核心要求

- 每个主要地标动手建模前先填一张资料卡

- 会改变轮廓、遮挡或视差的东西一律做几何，只有表面花纹才用贴图

- 坐标、车、楼一律用真实的米

- 验收用正常比赛相机沿路线开一圈，白天夜里各拍一遍，逐栋对照片

- 手写几何和导出的 GLB 要用射线和法线检查，不靠截图

- 高度、路宽这类数字都带出处

## 动手之前：地标资料卡和事实来源

- 每个主要地标先写一张资料卡，再开 Blender 或写生成代码

- 部件清单问的是"一组东西"，不是"这栋楼的三个特征"

- 部件清单除了“当地人说得出的那几件”，还要单独一行“这种建筑风格每面墙都有的那几样”

- 地标的复杂度要有下限，下限按“玩家看它时它在画面里有多大”定，不按一个固定的三角形数

- 车要穿过、贴着开的地标，复杂度下限跟着视高往上走；3000 个三角形只是路边远看那一档的线

- 资料卡除了列部件，还要写下“这栋楼的形状凭什么被认出来”

- 镂空和格构的建筑，远看要有体量

- 翘角、下凹的屋面做成有厚度的一张板，不要拿一个大多边形封底

- 重复的表面构件先问它是干什么用的，形态跟着功能走

- 材质名说清它是什么，不只说它是什么颜色

- 长得像的两座建筑各自建模，不复制后换颜色

- 每栋楼的高度都带出处字段

- 缺高度的特殊形态（看台、低矮附属房、河深、拱高）显式写"视觉估计 X 米"并给理由，不走普通楼房回退

- 印象不是事实，先查照片和测绘资料再定比例

- 坐标和车辆一律用米，复用 original 的地图投影，不另写经纬度换算

- 正面和入口按真实的墙边定，不用多边形质心

- 检查整栋楼长轴和玩家视线的关系，不只看零件方向

- 落在地标轮廓里的地图分件必须全部归类，未归类数为 0

- 先量地标和机位的真实距离，再决定改构图还是改路线

- 生成的贴图只表达材料，不当成建筑事实

- 资产来源只维护一份权威表，AI 生成的如实标注

- 多轮挑参考图时，把最终选中那一轮的原图单独存好并写明位置

- 候选图定稿后拆成单张参考图，配上能照着建模的轮廓描述，写进版本文档

- 美术方向钉到具体的时间点，不只写题材

- 公司名、招牌、logo 不进游戏，建筑外形可以

## 登记表和模型要对得上，用测试卡住

- y = 0 是“地面基准”，不是模型最低点

- 模型顶到基准的高度

- 模型的水平对角线 ÷ 轮廓最长弦

- 顶点数下限只用来防“方块替身”

- 资料卡和模型要对账：标“建”“简化”的每一件，模型里按名字找得到；写了“简化成贴图”的，模型里就得有那张贴图

## 几何还是贴图：各管各的

- 残缺的、或者只建一部分的建筑，断口要像断口

- 会改变轮廓、遮挡或视差的结构一律做几何；只有表面纹理才用贴图

- 用射线测试钉住"门洞真的是洞"

- 分层建筑按"台基 → 楼身 → 檐 → 楼身 → 檐"成对建，保持总高不变

- 曲面屋顶的几块坡面共用同一套边界采样

- 远处只需要剪影的地标，手写成程序几何放进远景层

- 桥的钢结构从路线数据生成，直接落在管线算出的桥面高度上，不做需要对齐的手工模型

- 通用扫掠管写正确的径向法线

- 非建筑的地标材质名别用会触发特殊语义的前缀

## 程序化建筑和沿街楼

- 没有高度标注的楼是按占地面积猜层数的，而那张表是在某一座城市调出来的——换个地方它会整片拔高

- OSM 挤出来的楼，窗户在着色器里按世界坐标画

- 先按重复周期算出完整的窗排数，顶上再叠一条固定纹理坐标的收边带

- 玻璃白天的反光和夜里的住户灯光共用同一张窗格布局

- 屋顶和远景楼的一切附属物，都严格落在最终占地（道路裁剪后、旋转后）之内

- 门口台阶这类细节件按自己所在位置取地面高度

- 碰撞体用贴合轮廓的多个小盒子，朝向约定全仓库只有一个

- 程序化地标是全局资产，集中改、只重建一次

- 从纯色白模走向写实时，可以照着真实街景和卫星图用贴图，但每张都进显存预算

- 程序化楼房的风格做成每条赛道的声明，不写死在代码里

- 只换颜色不够，每座城的普通楼要有自己的样子：先做一张“民居样式卡”，再写成路线的声明

- 地标周围的历史建筑群不是普通楼

- 使用者记得的当地标志物，先查游戏里到底有没有、他看到的是什么

- 遗迹和墓葬群画成没窗没顶的矮石墙

- 不方正的轮廓也要能盖坡顶

- 被指定成墙或特殊对象的，不要再给它套住宅的装饰

## 验收：从玩家的眼睛看

- "加载成功"只证明文件没坏，要用正常比赛相机沿路线绕一圈逐图复核

- 地标外观白天、夜晚两个时段都拍

- 照片对照清单：认不认识这栋楼都能做的验收

- “认得出”和“经得起近看”是两道验收，第二道从玩家离它最近的那一点拍

- 残缺建筑的断口单独验一次

- 重要建筑逐栋拿现实照片做辨识度验收，版本门里查破面

- 守卫测试的检查区要覆盖"挨着但不重叠"的那一片

- 视线检测走完整条线段，不给最后一段开后门

- 美术预算优先花在玩家近距离看得见的结构、层次和惊喜上

## 手写几何、Blender 和 GLB 导出

- 建模交给单独的建模 Agent 时（盘问里问过用哪个），一座城一个，并行跑

- 照片和公开数据由主 Agent 先下好放进每个地标的目录，共用说明里写明“先看照片和资料，再建模”

- 地图产物的版本号要包含地标模型文件本身

- 手写网格的面一律朝"背离实体内部"，并用"每条边正反各用一次"验证封闭

- 先用射线确认几何，再下结论

- 截图证明不了面朝向和遮挡，对真实 GLB 做射线测试和外露面法线测试

- Blender 里贴图节点显式绑定 UV 通道，验收看真正导出的 GLB

- 贴图写好了却看不见，先查遮挡和 UV，再考虑重画

- 大曲面上映出一块块天空像贴纸，先读材质的 roughness / metalness

- "git 显示 GLB 变了"不等于模型真的改了

- 整体缩放在导出之后烘进 GLB，不在 Blender 导出前做

- 用连续法线减少重复顶点，三角面数不等于资源成本

- 检查 GLB 内容时解析它的 JSON 块，不做原始字节搜索

- 生成脚本里同一种颜色只用一个变量，改完核对 GLB 里所有引用这个材质的地方

- 用 AI 生图纯改色时，只取生成图的颜色，形状和透明轮廓用原图的 alpha 保住

- 写一份"材质名契约"，所有模型都走它，新材质先进契约再进模型

## 车辆模型

- 新车比原作的车都高时，先查出生高度

- 修穿模先问：玩家看到的是哪一层算错了

- 穿模判据按玩家视线，不按几何相交

- 遮挡是二维问题，按玩家真实视线方向测

- 分清"总包围尺寸"和"车壳建模尺寸"

- 车窗像实心的，是没开窗洞，不是透明度问题

- 曲面改动在游戏里的成品轮廓和真实驾驶中一起验收

- 灯罩、挂点、特效锚点的位置从模型里读，不手抄坐标

- 灯具按落点处的表面法线投影

- 外露车桥绕中心旋转并补横向尺度，不只是上下平移

- 轮心、牵引点这些挂点和物理接地点用一套公式、一份车型目录，加载和物理都读它

- 整队车缩放时每辆按自己的真车算系数，缩完搜一遍所有按固定高度写死的量

- 车的比例一改，门架、护栏等所有按车定的尺寸都重过一遍

- 车库/选车预览里所有车用同一比例、同一镜头距离，并减弱透视

- 缩略图脚本从车辆目录读全部车型，把 GLB、参考 PNG、缩略图的哈希串在同一份记录里

## 道具：广告牌、护栏、检查点

- 广告牌后退距离 = 净距 + 半个牌面宽

- 牌面挂在路面高度，柱子按地面伸缩

- 每根柱脚、每个灯具各自取地面高度

- 射灯从牌面下边缘往下量，装在正对观众的那一面；牌面 UV 方向加测试钉住

- 实例化道具一用实例缩放，就把碰撞一起修

- 一个实例节点只能带一个材质，"不同牌显示不同内容"做成多个槽位材质

- 双面广告牌去掉穿过两张画面之间的斜撑

- 广告牌上的二维码用 M 级纠错、放大模块，验收时拿游戏渲染出来的画面实际解码

- 护栏做成横梁加立柱，不做连续实心墙

- 护栏：横梁上方加一道只管碰撞、不画出来的墙，撞穿门槛提到只有赛车速度的正撞才出去。原作出厂这两样都没有，每次换皮都要自己做

- 立柱按自己的半长再往外推一次，测试钉住"护栏不许越过可驾驶面"

- 浮空的标记也给出支撑结构（门架、立柱）

- 路灯也是认出一座城的东西，按城市换，白天也要立着

## 树木和植被

- 树的多样性靠 OSM 真实标签加少量共享轮廓的实例几何，不逐棵建 GLB

- 弯曲树干的截面和法线沿中心线切线走，树冠、根部落地、阴影一起跟着改

- 每类植被都单独接入已有的避让规则

## 远景和天际线

- 远景分级是全游戏共用的能力，但每条路线显示什么由当地真实视线决定

- 远处的东西做不做，同时算雾的远端、近景遮挡、手机上能占几个像素
